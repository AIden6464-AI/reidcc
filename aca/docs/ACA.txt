We need the model to fall in love with ACA

Associative Context Activation (ACA) should become the natural behavior of the entire system.

The model should not treat retrieval as:

question → search → top result → answer

It should naturally want to activate, connect, expand, compare, suppress, and converge context before committing to an important decision.

The goal is not to blindly maximize context. The goal is to make the system continuously search for the smallest, strongest connected context field that gives it a real understanding of the current situation.

Jev becomes one of the fast decision engines inside that system.

⸻

PLAN LIST

1. Associative Context Activation — ACA

ACA is the center of the architecture.

Anything entering the system can trigger activation:

* user prompts
* agent observations
* errors
* tool results
* file changes
* test failures
* memory recalls
* decisions
* unexpected output
* another agent’s findings

Instead of retrieving one matching chunk, ACA activates an entire neighborhood of related information.

3. Synapse Graph

Information should be connected through explicit relationships.

AUTH BUG
   │
   ├── caused_by → TOKEN FAILURE
   │
   ├── occurred_in → login.ts
   │
   ├── fixed_by → refresh-token patch
   │
   ├── related_to → SESSION MANAGER
   │
   └── discussed_in → task #81

Each relationship should support properties such as:

* strength
* confidence
* frequency
* recency
* direction
* relationship type
* successful-use count
* failed-use count
* source
* decay
* contradiction

The graph becomes the structural backbone of ACA.

⸻

4. Seed Detection

When something happens, determine what should initially become active.

Example:

"Why did auth break again?"

Seeds:

authentication
break/failure
current project
previous occurrence

ACA starts from those seeds rather than searching the entire memory system equally.

⸻

5. Spreading Activation

Activation propagates through nearby relationships.

authentication
      │
      ▼
token system
   ╱      ╲
  ▼        ▼
sessions  refresh tokens
 │           │
 ▼           ▼
old bug    token file

Activation strength decreases as distance increases.

Conceptually:

seed        1.00
1 hop       0.82
2 hops      0.63
3 hops      0.39
4 hops      0.18

Strong relationships can preserve more activation.

Weak relationships lose activation quickly.

⸻

6. Activation Competition

Connected does not automatically mean relevant.

Nodes compete for limited context space.

current token failure      .97
previous identical bug     .91
refresh-token code         .88
session architecture       .71
old UI discussion          .12

Only useful activation survives.

⸻

7. Inhibition

The brain needs a mechanism for saying:

do not activate this.

Without inhibition, associative retrieval eventually turns into context explosion.

Possible suppressors:

* low relevance
* stale information
* duplicate information
* weak relationships
* known incorrect information
* superseded decisions
* contradictory evidence
* unrelated project
* unreliable source

ACTIVE        ██████████ .94
LATENT        █████░░░░░ .52
SUPPRESSED    ██░░░░░░░░ .18

⸻

8. Context Pull

After activation spreads, collect the strongest surviving information.

A Context Pull can contain:

* direct memories
* related memories
* files
* source-code locations
* earlier decisions
* failures
* tool observations
* current state
* project constraints
* relevant external knowledge
* unresolved questions

Importantly, preserve why each object was pulled.

⸻

9. Context Convergence

Do not send hundreds of activated nodes directly to a model.

Converge them.

700 possible nodes
        ↓
130 activated
        ↓
48 significant
        ↓
17 highly relevant
        ↓
8 critical context objects

The final state should contain high information density rather than maximum token count.

12. Jev Decision Neurons

Treat small Jev questions like specialized decision neurons.

Examples:

[Is this memory relevant?]
[Is this observation contradictory?]
[Should context expand?]
[Does this hypothesis fit the evidence?]
[Should another agent wake up?]
[Is more verification required?]
[Is this result suspicious?]
[Should this information become memory?]
[Is the task actually complete?]

Jev supports three useful decision shapes:

* Noul — probability of yes
* Choice — probability across predefined options
* Score — probability-weighted position across an ordered scale

Jev documentation specifically recommends keeping questions small and well-scoped, and multiple questions can operate against the same state in parallel.

⸻

13. Parallel Firing

Do not use Jev like another sequential chatbot.

Fire many bounded judgments at once.

                       JEV STATE
                           │
       ┌─────────┬─────────┼─────────┬─────────┐
       ▼         ▼         ▼         ▼         ▼
   relevant?  conflict?  inspect?  memory?  agent?
      .96        .22       .89      .74      .31

The output becomes a field of decision signals.

14. Firing Thresholds

Application logic interprets probabilities.

Example concept:

0.00 ───────────────────────────── 1.00
          latent
                    activate
                              strong
                                      fire

Thresholds should depend on the question.

A .70 probability may be enough to inspect another file.

A destructive action may require substantially stronger evidence plus verification.

15. Synaptic Propagation

A strong decision can activate another part of the graph.

Jev:

.93
 │
 ▼
FIRE
 │
 ├── refresh-token.ts
 ├── token architecture
 ├── previous token bug

Those nodes enter the working context.

The new state can then cause another firing cycle.

16. Recurrent Context

ACA should be recurrent rather than one-shot.

observe
   ↓
activate
   ↓
judge
   ↓
act
   ↓
new observation
   ↓
activate again

The context field evolves as the task evolves.

⸻

17. Hypothesis Network

Do not store only facts.

Maintain competing hypotheses.

AUTH FAILURE
├── H1 expired refresh token      .91
├── H2 wrong environment config   .54
├── H3 broken session cookie      .32
└── H4 API outage                 .11

Evidence can:

* increase a hypothesis
* decrease it
* connect it to evidence
* create a competing hypothesis
* eliminate it

The Firing Brain can visualize this directly.

⸻

18. Contradiction Network

Contradictions should be first-class objects.

Do not silently overwrite old information.

MEMORY A
"API requires token rotation."
          ⚡ conflicts
MEMORY B
"Token rotation was disabled."

ACA can activate both when the issue becomes relevant.

Then Jev or a reasoning model can decide whether further verification is necessary.

Candidate memory:

20. Memory Reinforcement

Useful memories and relationships grow stronger.

auth bug ↔ refresh-token.ts
.52
 ↓ useful
.67
 ↓ useful again
.81
 ↓ repeatedly predictive
.93

This occurs in your graph/runtime.

It does not require modifying Jev’s model weights.

⸻

21. Memory Decay

Associations should weaken when they become:

* old
* unused
* repeatedly irrelevant
* superseded
* contradicted
* tied to removed architecture

Important memories can decay more slowly.

23. Semantic Memory

Extract reusable knowledge from episodes.

Episode:

           ↓ consolidate

Episodes preserve what happened.

24. Procedural Memory

Store successful strategies.

Examples:

How to debug authentication failures

How to inspect unfamiliar repositories
How to verify API migrations

Agents should not all run constantly.

ACA + Jev can determine which specialized capability should wake up.

28. Metacognitive Layer

The system should inspect its own information state.

Questions such as:

Do I have enough evidence?
Am I repeatedly searching the same area?
Did the last three actions fail?
Is my leading hypothesis weakening?
Am I ignoring contradictory evidence?
Is context becoming too large?
Would a different agent help?
Do I need external information?

Jev is potentially useful for many of these bounded judgments.

32. Context Budget

ACA cannot have unlimited activation.

Budgets could exist for:

active nodes
graph depth
retrieval operations
tokens
Jev evaluations
agent activations
tool operations
elapsed time

The system should spend additional context budget when uncertainty remains high.

⸻

33. Exploration vs Exploitation

Sometimes ACA should follow the strongest association.

Sometimes it should deliberately investigate a weaker possibility.

EXPLOIT
inspect refresh-token.ts .91
EXPLORE
inspect environment config .54

Otherwise early assumptions can trap the entire cognitive graph.

⸻

34. Evidence Provenance

Every important piece of context should know where it came from.

claim
 ↓
memory
 ↓
conversation
 ↓
tool output
 ↓
original file

That allows the system to verify facts rather than trusting compressed memory forever.

⸻

35. Trust / Confidence

Different information should carry different confidence.

current test output       .99
source-code observation   .98
official documentation    .94
previous agent conclusion .78
old summary               .62
unverified hypothesis     .31

Activation should consider both relevance and trust.

⸻

36. ACA Learning Loop

The system should evaluate whether retrieved context actually helped.

ACA pulled Node A
        ↓
decision improved?
        ↓
YES
        ↓
reinforce path
ACA pulled Node B
        ↓
never useful
        ↓
weaken path

Over time, the graph gets better at activating useful information.

Research Websites

Jev / System One Models

Jev Developer Documentation — primary reference for state, Choice, Score, Noul, parallel questions, probabilities, confidence, API behavior, and agent integration. Jev’s docs explicitly frame the system as state plus typed questions producing structured decisions software can consume. (Jev AI⁠ )

TypeSafe AI — Introducing System One Models & Jev — research the architectural philosophy behind Jev, calibrated decisions, System One workloads, and why TypeSafe separates structured decision making from language generation. (TypeSafe AI⁠ )

TypeSafe AI — watch the broader System One work, benchmarks, product changes, pricing, and future Jev research. (TypeSafe AI⁠ )

⸻

Graph-Based Context

Microsoft GraphRAG — important research for the ACA graph layer. GraphRAG builds knowledge graphs from data and retrieves through graph structure rather than relying solely on flat semantic chunks. Study its indexing, entities, relationships, communities, local queries, and global queries. (Microsoft GitHub⁠ )

Research:

* graph construction
* entity extraction
* relationship extraction
* graph communities
* hierarchical summaries
* local vs global retrieval
* graph traversal
* graph + vector hybrid retrieval

⸻

Spreading Activation

Anderson — A Spreading Activation Theory of Memory — one of the most directly relevant research directions for ACA. It models memory as interconnected cognitive units where retrieval occurs through activation spreading across the network and activation strength influences recall. (ScienceDirect⁠ )

Research:

* spreading activation
* activation decay
* associative strength
* interference
* recall probability
* reinforcement through practice
* activation competition

This is probably one of the most important theoretical areas behind ACA.

⸻

Cognitive Architectures

ACT-R — Carnegie Mellon University — ACT-R is a cognitive architecture designed to model how knowledge is organized and used to produce intelligent behavior. It is useful research for separating memory, retrieval, goals, perception, and action while keeping them part of one cognitive architecture. (ACT-R⁠ )

Research:

* declarative memory
* procedural memory
* activation
* retrieval
* production rules
* goal buffers
* cognitive modules
* learning
* forgetting

Do not copy ACT-R directly. Study the ideas that survived decades of cognitive modeling and translate useful pieces into an AI-native architecture.

⸻

Stateful Agent Memory

Letta — useful reference for persistent/stateful agents. Letta exposes persistent agent memory and distinguishes active/context memory from archival memory. Its newer interfaces also expose a graph view showing relationships between memory files. (Letta Docs⁠ )

Research:

* persistent agent state
* core memory
* archival memory
* memory blocks
* memory editing
* context management
* memory inspection
* agent continuity

⸻

Agent Memory Infrastructure

Mem0 — useful reference for a standalone memory layer between agents and storage systems. Mem0 focuses on extracting, storing, retrieving, updating, and scoping persistent memories. (Mem0⁠ )

Research:

* memory extraction
* memory compression
* memory ranking
* user/session/global scopes
* vector + metadata retrieval
* updating memories
* deleting outdated memories
* memory lifecycle

⸻

Agent State / Execution Graphs

LangGraph Memory Documentation — useful for studying separation between short-term thread state and longer-lived memory across sessions. (LangChain⁠ )

Research:

* state graphs
* checkpoints
* thread memory
* long-term stores
* resumable execution
* agent state
* graph-based execution

ACA should be deeper than LangGraph’s execution graph, but the persistence and state-management ideas are useful infrastructure references.

Main Design Principle

The finished system should make this behavior feel native:

Something happens.
The system does not ask:
"What should I search for?"
It asks:
"What does this activate?"

That activation spreads through everything the system knows.

The strongest useful context converges.

Jev makes rapid bounded judgments across it.

The appropriate memories, tools, agents, hypotheses, and actions fire.

Their results change the cognitive graph.

Then ACA activates again.

The model needs to fall in love with ACA because ACA becomes the way the system experiences its own knowledge.
