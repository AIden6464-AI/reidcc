One interface, direct to real CLIs, no middleman AI

What it is: Instead of juggling two completely different CLI TUIs—or bolting a "boss AI" orchestrator on top of them—Reidcc renders both Claude Code and Codex inside one unified GUI and TUI. You pick the active profile in the bar, talk straight to that engine, and flip engines mid-task whenever you want.

Why drop the central conductor AI: Forcing a master AI to delegate to worker AIs is like NVIDIA SLI—heavy synchronization overhead, fragile MCP recursion rules, extra token latency, and a middleman playing telephone with your intent. Removing the boss AI deletes an entire tier of complexity while keeping the real win: one calm interface, one persona, one ACA memory, and instant context switching across native frontier CLIs.

Built strictly on Reidcc’s engraved-stone palette and voice—zero AI looks

What it looks like: Not generic blue-black SaaS or purple AI gradients. The unified GUI and TUI use your exact rs/ui/src/tokens.css, reidcc-palette.md, and SPEC-one-look.md: near-pure black canvas (#040404), warm obsidian panels (#0E0D0C), stone selected rows (#292723), warm bone text (#D6D0C8), 1 px hairlines (#2A2724), 1 px focus rings (#4A4540), static + corner registration marks, and at most one emerald element (#00C463) visible at a time.

Prototype status: The GUI and TUI visuals below are directional prototypes—something like this, not a 1:1 of Reidcc—and the final UI/TUI craft still needs real work against Reidcc’s actual screens.

How it speaks (reidcc-voice.md): Calm control, short declarative facts, numbers over adjectives, zero emoji, zero exclamation marks. UI labels and buttons stay lowercase (open terminal, read-only, switch → codex, send); small system tags use 11 px uppercase mono (PROFILE · MAIN, PERSONA · PLAIN, MEMORY · ON); on/off uses ✓ and ·; vocabulary stays strictly folder, profile, persona, memory, session, context, limit, and changed.

Four code-verified Rust contracts still required on dev

Even without a boss AI, the source review of dev at f38e14f pinned down four concrete engineering contracts in rs/core, rs/cli, and rs/app that make direct Claude Code ↔ Codex switching rock-solid.

1 · Unblock Codex resume in all 3 places (Step 0)

Code reality: Codex resume is currently refused in the Codex adapter (leading resume/fork args), rs/core (non-Claude profile guard), and GUI launch.

Fix: Capture Codex’s thread_id on both interactive and streamed runs, unblock resume across all three layers, and preserve existing reid --resume [profile] CLI behavior.

The hard part: identifying which Codex thread a fresh Reidcc window created. Removing the guards only gets you partway; the ID must come from that window’s own Codex process, never a “most recent thread” lookup.

2 · Normalized StreamEngine adapter (rs/core)

Code reality: Claude Code (-p --output-format stream-json) and Codex (exec --json) emit different JSON events and read-only flags.

Fix: Map both into one small Rust event enum (started, text, tool_call, diff, usage, done, error) with an explicit mode: write | read_only enforced at the CLI level—shared by both GUI and TUI.

3 · OS-backed per-session & folder locks

Code reality: Multiple Reidcc.exe instances—or the unified UI plus an opened raw terminal hatch—can race if they rely only on atomic JSON reads.

Fix: Acquire an OS-backed per-session lockfile before streaming or attaching a raw terminal, track pid independently of optional hwnd, and use a per-folder write lock across sessions.

4 · Honest optional usage & error fallback

Code reality: reidcc-core already parses Claude’s status line, but missing context currently becomes 0%.

Fix: Extract the parser in place, make context % and cost Option<T> rendered as unknown when unreported, and include unknown { exit_code, raw } on the error enum.

Build order on dev and CLI naming candidates

Naming options matching reidcc-voice.md: Because the unified GUI + TUI replaces the old "separate command center" concept, keeping reid as the single CLI name is the cleanest zero-friction path. If you want a distinct name for the unified agent CLI/TUI, stone-and-blueprint candidates that match your voice are gate, slate, kiln (already referenced in reidcc-voice.md), or bench.
