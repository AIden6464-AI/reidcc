## Must fix

### 1. The window drops save errors
`rs/app/src/model.rs:225-227`
- **Problem:** `Model::save` throws the error away (`let _ =`). The TUI (`rs/cli/src/tui.rs:189`) reports the same error, so the two apps follow different rules. Saving swaps a temp file into place, and Windows refuses the swap while another program holds `reid.json` open (an antivirus scan, OneDrive, Python `reid.py`). The window still shows the change, but the file never got it, and a `reid.json.<pid>.tmp` is left behind.
- **Fix:** Have `save` return the error and add an error `Say` op, as `cfg()` does. In `save_json` (`rs/core/src/lib.rs:189`), delete the temp file when the swap fails.
- **If skipped:** Now and then a profile edit disappears with no message.

## Should fix

### 2. The `reid://` asset handler can read any file
`rs/app/src/main.rs:499-508`
- **Problem:** It only blocks `..`. `http://reid.localhost/C:/Users/you/Reidcc/json/api.json` becomes a full Windows path, and joining a full path replaces the base folder. So any page in the app can read your key files, and the handler allows every origin (`Access-Control-Allow-Origin: *`). Today only your own pages load, so nothing can use it yet.
- **Fix:** Serve only paths under `assets\` and refuse anything with `:`. Drop the CORS header.
- **If skipped:** The first remote page or link in a webview can read your keys.

### 3. `proxy/proxy.py` is dead code
171 lines, plus `fastapi`, `httpx` and `uvicorn` in `proxy/requirements-dev.txt`
- **Problem:** Nothing starts it (profiles use the mitmproxy add-ons). Only `tests/test_optimize_payload.py` imports it, so `optimize_payload` exists twice and has to be kept in step. Importing it also creates an `audit/` folder.
- **Fix:** Delete `proxy.py` and the three packages. Keep only the add-on cases in the test.

### 4. No test in CI for the trimming and parsing logic
`rs/core/src/memory.rs:114` (`trim_memory`), `rs/core/src/engines/codex.rs:197` (`provider`)
- **Problem:** CI runs 13 Rust tests and neither function has one. The `rs/tests/*.py` parity scripts cover them only when run by hand. A mistake in where the trim cuts could drop the pinned facts, and a bad nested key in `provider` would send Codex the wrong config.
- **Fix:** One `#[test]` each. `trim_memory`: long memory with non-ASCII text, where the pinned facts are kept and the newest journal lines survive. `provider`: a nested table becomes dotted `-c` keys and `[env]` goes to the environment.

### 5. Two sessions of the same profile share one proxy log
`rs/core/src/proxy.rs:306-307`
- **Problem:** `File::create` empties `proxy\logs\<profile>.log` while the first session's mitmdump still writes to it. With rigs, the same profile twice is normal. Both logs end up mixed and full of gaps, and the "proxy didn't start" message can show the other session's lines.
- **Fix:** Name it `<profile>-<port>.log`.

### 6. The Python app duplicates the Rust app
`python/` ≈ 4,200 lines, plus parity scripts ≈ 1,100 (`rs/tests/parity.py`, `tui_parity.py`, `gui_parity.py`)
- **Problem:** Any change in behaviour has to land in both languages.
- **Fix:** Once stage 1 is signed off, delete `python/` and the scripts that compare against it.

## Nice to have

### 7. The "kill the process and its children" code exists three times
`rs/core/src/session.rs:29`, `rs/core/src/proxy.rs:347`, `rs/app/src/session.rs:368`
- **Problem:** Each copy runs `taskkill /F /T` and then waits, with small differences (only one hides the console window).
- **Fix:** One `win::kill_tree(pid)` in core, called from all three places.
